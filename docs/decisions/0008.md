# ADR 0008：LAN 桌面直连、用户代理与首个画面基线

状态：Accepted · 2026-10-16

产品接入保持 ADR 0007：无账号、配对或逐次批准，信任同一直接 LAN。TCP 45832 与 Host 直连，不涉及外部握手服务器。
传输使用 .NET SslStream / Windows Schannel TLS 1.3，ALPN pc-remote/2。自动生成服务本次运行的 ECDSA 证书，不弹证书确认；没有首次身份认证或主动中间人防护承诺。TLS 在此提供传输加密，不把它描述成账号身份认证。证书通过默认 PKCS12 导入建立 Schannel 兼容的临时本机密钥容器，随证书释放清理，内存 PFX 及时清零。
控制帧仍是长度前缀 JSON，但首个实际桌面消息定义为独立 major 2/minor 0，拒绝 Foundation 的 major 1；发现仍为 2.0。

服务只允许一个活动桌面会话。接受前校验真实 TCP 本机端点、来源同子网和同接口直接路由，每 2 秒复验。TLS/代理连接 10 秒超时，控制端每 3 秒 Ping，收到半帧/超时/未知消息即结束。服务不执行来自网络的命令、路径或程序名。

服务通过 WTSQueryUserToken 取得当前活动控制台用户令牌，管理员存在 UAC 完整/受限令牌对时选择受限令牌。CreateProcessAsUser 仅启动已安装的同一个 Host EXE --agent，显式 winsta0/default 与用户环境。不支持无用户登录、RDP 会话选择、锁屏或 UAC 安全桌面。
IPC 每会话随机 pipe 名；DACL 只授予 LocalSystem 和目标用户；服务验证客户端 PID 等于本次启动的进程，代理验证 pipe 服务端 PID。当前控制台会话变化或断线时关闭 pipe、等待退出，超时终止同一个进程句柄。Capture/Input 不在 Session 0 执行。

首个画面基线使用 Windows GDI CopyFromScreen → JPEG quality 60，最大宽 1280、约 10 fps（实际受采集和网络背压约束）。源屏幕最大 8192 边长/33,177,600 像素；单 JPEG 600 KB，控制帧总长 1 MiB。客户端验证声明尺寸与 JPEG 头尺寸一致，UI 只保存最新一帧，避免队列堆积。画面两秒未更新立即遮罩并停止输入。
替代方案：WGC/D3D11 + 硬件 H.264 更适合 1080p60，仍是后续优化路线；先用可替换 IScreenCapture 验证服务/用户会话/输入完整链路，避免把 WinRT/D3D 互操作与会话问题混为一体。此基线不宣称已达到产品性能目标。
键鼠使用 SendInput，坐标以主屏归一化后映射虚拟屏，输入消息枚举/范围严格校验。失焦、画面不可用、队列溢出与断线释放按键/鼠标。无法绕过 UIPI 或发送 Ctrl+Alt+Del；安全桌面期间失败的释放在恢复后重试。
后果：这是可编译的初始远控实现，真实双机、多 DPI、锁屏/切用户/提权窗口矩阵尚未完成。文件传输不在本次实现中。
