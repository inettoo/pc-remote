# ADR 0009：先完成基础闭环与用户文件传输

状态：Accepted · 2026-10-16；补充 ADR 0007/0008，取代原路线中先做性能再做文件的顺序。

背景：用户希望持续开发并保持“单 EXE 自动装服务、控制端直接控制”，因此先补齐发现、画面、键鼠、文件的基础闭环，高帧率/输入兼容优化继续后续版本。

文件操作只在当前用户代理执行，服务仅桥接白名单消息，不使用 LocalSystem 读取/写入用户文件。默认共享根是该代理用户的 UserProfile，界面称“用户文件”，没有额外配置/授权步骤。
支持列表、上传、下载、进度、取消；不执行文件，不提供远端删除、重命名或创建目录。每次一个活动传输，最大 1 GiB，32 KiB 块；目录最多返回 128 项，扫描最多 256 个候选，隐藏链接/联接/云占位及上传临时文件。
共同 FilePathRules 拒绝绝对路径、.. / .、ADS、控制字符、设备名、尾点/空格和超长相对路径。RootedFiles 验证根前缀与现存路径上的 ReparsePoint。约束用于远程文件 API，不把同权限本机进程可变更的本人目录描述为隔离沙箱；用户代理不继承服务的系统权限。
上传写同目录随机 .partial 文件，严格偏移/长度/SHA-256 后同卷原子移动；同名拒绝，取消/错误删除自己的临时文件。下载在控制端也写临时文件，完整性验证后才提交；覆盖只发生在用户通过保存对话框确认的本地目标。
控制协议升 major 3 / minor 0，ALPN pc-remote/3，发现仍 2.0。Envelope.requestId 是操作相关 ID；帧与文件共享连接。代理写入用单一信号量序列化，客户端只有一个网络发送循环，避免帧交错。
上传每块等待 FileAck，避免文件占满输入队列；下载最多 8 条待处理响应。队列/尺寸/超时有界，背压可能暂时降低画面帧率，不堆积无限数据。请求结束会关闭邮箱并忽略迟到响应，取消只针对当前传输 ID。
实际 TCP/TLS 由可注入 IDesktopConnector 封装；生产始终使用 TlsDesktopConnector。测试替身只在测试程序集，真实 named pipe 验证客户端/代理的文件往返，不安装服务、不操作真实屏幕或键鼠。
Windows pipe 客户端显式请求 ReadWrite 精确权限，避免 GENERIC_WRITE 隐含创建 pipe 实例权限。控制端本地会话锁定/注销/断开时结束远控。
UI：远控窗口“用户文件”打开文件列表，双击文件夹进入、双击文件下载，上传使用标准文件选择对话框。没有网络设置、账号或连接批准页面。

后果：目前不是完整资源管理器；云占位/链接、超大目录与 >1 GiB 文件有明确限制。WGC/硬件编码、高 DPI/系统组合键、多机和锁屏矩阵仍待后续验收。
