# ADR 0007：单 EXE 安装常驻服务与无交互的 LAN 接入

状态：Accepted · 2026-10-16；替代 ADR 0002、0003 的无服务限制及 ADR 0005 的密钥/预授权交互。

背景：用户明确要求被控端运行一个 EXE 自动安装服务，控制端直接控制，不要求授权、网卡选择、账号或配对口令。

决策：Host 发布为自包含单 EXE，默认启动即安装至 Program Files/PcRemote，注册并启动自动启动的 PcRemoteHost Windows 服务。已有提升权限时直接安装；否则由 Windows 正常请求管理员提升，不绕过操作系统权限。安装后随系统启动，日常连接不弹确认。
控制端发布独立自包含 EXE，启动自动发现设备，后续选中即可控制。LAN 接入不设账号、配对密钥或逐次批准：服务启用即信任同一直接局域网中的控制端。此模型不提供对同网段其他用户的身份隔离。
服务负责发现、连接生命周期与桌面代理管理。屏幕和输入必须由交互用户会话代理处理，禁止在 Session 0 假装采集桌面。服务运行 LocalSystem 为后续 WTS 用户令牌/启动代理做准备；网络处理只允许固定协议和边界，不执行远端命令、不暴露任意系统文件操作。
v0.0.2 只实现安装/启动/卸载、服务 UDP 发现与控制端自动发现，没有远控操作接口。用户不应把该版本当成已能控制。
安装器只写固定程序目录、固定服务名、固定程序的 UDP 45831 LocalSubnet 防火墙规则与 Application EventLog source。不修改网络分类、不递归删除目录；现有同名服务路径不匹配时拒绝覆盖。--uninstall 停止并移除服务和其规则，保留二进制/事件历史。
--quiet 仅用于已有管理员权限的自动化安装测试，不触发自动提升；--diagnose 不做更改。

依赖：新增微软 System.ServiceProcess.ServiceController 10.0.13（MIT），使用官方 SCM/ServiceBase 生命周期。比手写服务分派器更易维护；固定版本并随 .NET 维护更新。
替代方案：要求用户手动运行 sc.exe 或选网卡不符合需求；无服务便携 Host 无法满足开机常驻；交互服务与 Session 0 隔离不兼容。
后果：单 EXE 更大，但不要求目标安装 .NET；首次系统服务安装仍受 Windows 管理员权限约束。服务生命周期在 GitHub Windows runner 中做安装/监听/卸载集成测试，双机与用户桌面代理另行验收。
