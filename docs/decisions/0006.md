# ADR 0006：自动探测与有界 UDP 请求/响应

状态：Accepted · 2026-10-16

控制端启动后自动识别可用 Ethernet/Wi-Fi 类型接口上的 RFC1918 IPv4，不显示或要求选择网卡。
每个地址使用绑定该地址的临时 UDP 端口，每 2 秒向子网 UDP 45831 发送 probe，TTL=1，指定 Windows IP_UNICAST_IF。
被控服务绑定 UDP 45831，使用 packet information 校验来源接口；只回复同一 RFC1918 子网、非本机/网络/广播地址且 GetBestRoute 确认为同接口直接路由的 probe。回复带回 scanId，控制端必须匹配自身扫描 ID。
Windows Public/Private/Domain 标签不作为用户操作门槛；局域网边界由地址、接口和直接路由确定。不能访问公网、IPv6或通过网关路由的目标。虚拟以太网亦可能属于直接局域网，不声称识别所有 VPN 软件。
发现协议 2.0 独立于控制帧协议 1.0；相比早期草案改为 probe/host 请求响应，不与公告草案兼容。
最大 512 字节；拒绝重复/未知字段、畸形 JSON、截断和未知版本。每秒最多处理 64 包、目录最多 128 项、7 秒过期；不信任设备名称/ID，不因此授予身份信任。
控制端只有主动发送后的临时 UDP socket，减少固定入站端口配置；被控安装器添加限定自身 EXE、UDP 45831、LocalSubnet 的防火墙规则。
自动发现持续重读接口，变化后自动重建，退出取消全部任务并释放 socket。无网络时等待，不要求用户配置。
代价：防火墙/广播隔离仍可能阻止发现，真实双机验证仍是发布门槛。

原生接口参考：https://learn.microsoft.com/windows/win32/api/iphlpapi/nf-iphlpapi-getbestroute
